# 教学目标与讲解方案

以学生能看懂、教师能判断是否合适为标准，每组写一篇连贯的 Markdown。结构随内容调整，不强制表单，也不制作逐幕分镜。

方案交代清楚：

- 面向什么基础的学生，学完能理解、辨认或使用什么。
- 本课围绕什么核心问题展开，各目标词怎样共同回答它；选定词义与用法，区分重点和理解重点所需的辅助内容。相关知识不自动成为教学目标，例句里的语法不必逐项展开。
- 准备借助什么情境、例子或动作解释，为什么这个讲法有助于理解；给出少量具体例子，让用户能判断教学思路。
- 大致如何引入、推进和收束，让学生知道为什么从一个词讲到另一个词。故事、对比或动作服务于词汇关系，不为串词强编情节。
- 哪些关键理解值得让学生试一试，给出少量候选练习及判断依据。候选不等于全部采用，也不要求每个知识点各出一道题；用户明确指定的练习另行保留。
- 影响教学决策的假设、待澄清问题和能力限制；只提会改变本课讲法或练习选择的事项。

采用构词关系时，说明构成部分在当前词中的作用，并连到整词含义与用法；对有迁移价值的常见规律，可简述其常见作用与适用范围，用学生容易理解的例词帮助举一反三。辅助例词不自动新增为学习目标或练习项。区分词根、基词、词缀及拼写变化，不把所有字母相似的词都当作同源派生。采用辨析或情境关联时，解释它们在相同情境中的区别和选择依据，不强凑词根词缀。

这个阶段确认的是教学范围和思路。不要扩展成逐句台词、逐幕画面、动画时间表、预计时长或完整课程代码。讲解顺序、实际台词、画面与互动的共同设计属于下一阶段。

方案面向用户判断教学内容。批次编号、目录、尺寸校验、播放器接入、制作进度等信息留在批次记录或主会话摘要，不重复插入每篇方案。保留标题与方案版本；没有实质问题时不追加技术限制或自检清单。

交付前一次检查：目标词是否有遗漏、学习目标与练习是否对应、关联依据是否成立、是否违背用户要求。发现具体问题直接修改，不必在方案里报告检查过程，不为每份方案自动建立多轮审查流程。必要时核对可信资料，避免为了套用关联方式编造结论。
