# 联合课程脚本

本阶段细化已确认方案中的课程走向、核心场景和基础台词：将口播拆成实际朗读条目，同时细化画面变化、素材与互动。输入是本组最新已确认方案、原始要求、尺寸、参考资料及批准记录。不同组不借用彼此的确认。

## 设计与讲解

沿已确认的主要顺序细分片段和填写字段，不重新选核心情境或另编故事；先按方案基础台词润色，再与对应动画共同细化。保留开场交代课程方向、关键词义衔接和结尾收束，镜头细分不自动增加教学段落。visualDirection 概括已确认走向及本次视觉表达，不另起一套讲解主线。只有措辞、镜头、布局和动作的实现调整可直接细化；改变教学目标、范围、核心场景、主要推进顺序或互动安排时先修订方案并重新确认。

按已确认方案中的主次设计：展开重点时让学生观察和理解，基本认识落实到简短台词或例句，备选内容不默认制作。关联讲解承接方案指定的词义，并说出转换依据；不因某个常用意义不便画成当前场景就省略。不要将方案中的每个知识点各变成一段；能共同说明一件事的解释、例句与拼写提示合在同一推进中，不按“每词一页”或固定标题、定义、图片、例句的模板排列。不得静默删改明确批准的目标、范围或用户指定的题目。若接续的旧方案遗漏必要的基本知识或目标偏离词汇学习，先提出具体范围修订并按方案确认规则处理，不沿用缺陷，也不擅自扩展已确认范围。

- 每段解决一个明确的理解问题。speech 是实际会读出来的台词，不写“这里解释词缀”等制作指令。把已确认方案中的关键关系、用法和区别说出来，不能仅在画面或脚本备注里出现。英文单词和例句朗读使用独立 en 条目，中文解释使用 zh 条目。
- 课程方向交代之后，讲具体知识时可先给可理解的例子或观察对象，再用自然的话解释；“先举例”不替代整课引入。台词围绕眼前的词句解释含义、形式和用法，保留必要的术语和构词解释。创作者的准确性判断用于选准例子与措辞，不转成备课笔记、通用学习劝告或审查结论的口播。必要的适用边界随对应词句简要说明，不因此另开行为评价或常识讨论。
- 遇到有迁移价值的常见规律，在当前词的解释上补一句常见作用，必要时用简短、可靠的例词说明，再回到本课。表述标明适用范围，避免把常见用法说成绝对规律；不因补充例词另开词汇讲解或配题，也不机械追加“这里不展开”等收尾话。
- 每段写明学生先看到什么、主要看哪里、图文怎样组成整体。说明共同边线或中心关系、相邻说明归属、对比元素的对应位置；字词附着在解释对象附近，箭头连接实际对象。人物动作有助于教学时保留人物及其动作，不只用几个静态文字框代替情境。
- 按表达需要选择画面材料：人物、物品、环境可使用生成的静态插画，精确文字、构词变化、指示线和需要连续演示的动作使用可控制的图形与动画。需要插画时在 visual 中说明主体、构图和与动画元素的关系，素材生成留到画面制作阶段；不因代码能画 SVG 就把所有对象都画成简笔图，也不为增加图片而拆散同一教学动作。
- 画面变化绑定具体台词：什么对象从什么状态变成什么状态，变化帮助理解哪句话。让学生先有观察和理解对象，再引出下一层信息。同段内讲解重点改变时，也说明旧内容保留、弱化或退出，以及新的视觉中心；不把一段等同于一张持续堆加内容的页面。标注与被说明对象作为一组设计出现、移动和退出；提前引入概念时，先给出可见对象再解释。换段说明保留或撤去什么，第一帧不提前出现后段内容或答案。需要观察的动作可注明观察意图，不为每句话机械添加长停顿。
- 布局服从本次宽高，给固定字幕区域留出空间；本阶段只描述相对关系，不猜播放器的具体像素边界。尺寸留在 videoSize，不逐段重复横竖屏等制作参数。白底双色和固定播放器沿用内置规范，不能自行重设计播放器。
- 细化方案已选定的练习及其位置，备选题不自动加入。每道互动都要让学生运用刚学的目标词知识，并在所属 beat 的 purpose 中写清所用知识和本题作用；仅凭一般常识即可作答、无需理解或使用目标词的行为判断不作为词汇练习。图片和情境可作为判断词义或用法的证据，不把评价情境中人物的行为本身作为学习目标。讲解中的设问由教师接着解释，观察提示随画面继续，只有方案确定需要暂停作答的才写入 interaction；发现题意或答案问题时按上面的变更边界处理。
- 有互动时，题目、答案、反馈与讲解目的相符。单选题逐项核对语境中是否确实只有一个成立的答案，不能只因合法表达不同于所教模板就判错；必要时改清题意或换干扰项。答案和解释在作答后展示，不混入答题前台词或初始画面。跟读当前仅写入预留清单，不产生等待录音、评分或点击继续的活动关卡。

本阶段不估计总时长，不生成时间戳或按估计语速分配秒数。以台词开始/结束作为画面变化的逻辑锚点；真实时间由后续音频生成后确定。

## HyperFrames 的位置

具备相关 skills 时，先读 hyperframes 入口，再使用 hyperframes-creative 的画面组织和 beat-direction 指导；不要在此阶段启动 init、素材下载、TTS 或 render。只加载当前设计需要的内容，不另起其完整视频工作流。
本产品的教学要求优先：不套用营销视频的固定元素数量、装饰背景、快速转场或默认 16:9。保留有教学作用的动作与清晰的图文关系。若相关 skill 尚未可用，记录制作依赖待补，仍可按本文件完成脚本；进入实际动画实现前再解决依赖，不假称已经使用 HyperFrames。

## 一份源文件，一份自动生成的阅读版

写 groups/<组目录>/script-vN.json，字段如下。字段组织制作材料，不规定课程页面布局。

| 字段 | 内容 |
| --- | --- |
| schemaVersion | 固定 "0.2" |
| groupId、version、planVersion | 本地组编号、本脚本正整数版本、批准方案正整数版本 |
| planSha256 | 所读方案原文件的 SHA-256；用程序计算 |
| title、videoSize | 本课标题、实际 width/height |
| visualDirection | 本课的情境与整体图文组织方式，一段简短说明 |
| beats | 按播放顺序排列的讲解片段，见下表 |
| coverage | 已确认的关键教学点如何落实到实际台词：每项为 point 和 speechIds；编写时对照原方案，不新增教学范围 |
| reservedReadAlong | 可选数组，仅在确有跟读需求时记录 afterBeatId 与 text，默认空数组 |

每个 beat 使用：

| 字段 | 内容 |
| --- | --- |
| id、purpose | 稳定的片段编号、本段帮助学生理解什么 |
| speech | 有序数组，每项为 id、lang（zh/en）、text；id 在整课唯一，text 为实际台词 |
| visual | layout（布局关系）、initialState（刚进入时可见的内容）、cues（每项为 speechId、at=start/end、action，描述对应变化）、handoff（如何接到下一段；末段如何收束） |
| interaction | 没有则 null。有则是本段台词结束后触发的选择题：type="choice"、prompt、options（每项 id/text）、answerId、feedback（correct/incorrect，给出解释和纠错依据）。脚本阶段描述数据，动画打包阶段接入固定交互组件 |

语音后的题目反馈与普通 speech 分开存放，避免默认播放时泄露答案。coverage 引用本课真实台词 id；它是供核对的索引，不是凭填写“已覆盖”就自动通过的证明。标题和画面说明只写课程内容；测试来源、工具读取过程和能力声明留在批次记录，不混入学生台词或课程设计。

用随 skill 提供的工具检查并生成阅读版：

    python3 <skill目录>/scripts/script_tool.py <组目录>/script-vN.json --batch <批次目录>/batch.json --group <本地组编号>

工具检查批准版本、方案摘要、编号引用、互动答案、基本结构，并生成同名 .md。不得跳过失败项或手改阅读版掩盖源数据问题。主会话核对输入尺寸是否正确，工具不负责自行猜测不同来源 input.json 的格式。

之后做一次连贯阅读：按学生的播放顺序读台词并对应画面，判断开场是否给出方向、转折是否有来由、解释是否具体、作答是否打断理解；连读整课中承担回顾作用的段落，判断每次重现是否有新的教学作用；功能相同的重复归并，不靠换布局掩盖重复台词。再对照确认方案核对关键内容与答案是否提前泄露。coverage 用来查缺漏，不用来扩充课程。结构检查不证明教学正确、台词自然或画面好看。发现明确问题就修正，不增加无目的审查轮次；需要改变方案范围时返回用户确认。

主会话保存脚本版本和链接、更新 script_ready；按入口接续 [配音与实测时间](audio-timing.md)。脚本不是已渲染画面，不能声称完成逐帧检查或实际配音同步。
